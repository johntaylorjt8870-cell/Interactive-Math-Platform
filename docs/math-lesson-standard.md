# معيار الدرس الرياضي — Math Lesson Standard

> هذا الملف يجيب على سؤال واحد:
> **«لو درس طالب الصف الثامن هذا الدرس وحده، هل سيفهم المفهوم فعلًا؟»**
> إن كانت الإجابة «سيقرأ الكتاب نفسه فقط» فالمهمة لم تُنجز.

---

## 1) الحفاظ + التوسيع (لا تناقض بينهما)

| الحفاظ يعني | التوسيع يعني |
|---|---|
| لا حذف أي عنصر من الكتاب | شرح أوضح للفكرة |
| لا اختصار للشرح الأصلي | حدس ومثال محسوس |
| لا إعادة صياغة تُفقد المعنى | تعليل كل خطوة |
| لا تغيير في الترتيب | أخطاء شائعة وكيف نتجنبها |
| لا تغيير في المعنى الرياضي | تمارين وتفاعلات ومراجعة |

كلاهما **مطلوب معًا**. لا تُقبل الحجة: «اختصرنا الشرح ليكون تفاعليًا».

---

## 2) عمق الشرح: ما يُتوقّع ذكره عند الاقتضاء

لكل مفهوم، اسأل نفسك: هل شرحت…

- [ ] **ما معناه** بلغة يفهمها طالب الصف الثامن؟
- [ ] **لماذا يهم** وأين يظهر في الرياضيات؟
- [ ] **كيف نتعرف عليه** في مسألة جديدة؟
- [ ] **كيف نطبّقه** خطوة خطوة؟
- [ ] **لماذا كل خطوة** (التعليل) — وليس فقط «نطبّق القانون»؟
- [ ] **ماذا تعني الرموز** المستخدمة؟
- [ ] **كيف تعمل العلاقة الرياضية** (الحدس قبل القاعدة)؟
- [ ] **الأخطاء الشائعة** المتوقعة فعلًا؟
- [ ] **كيف نتحقق** من صحة الجواب؟
- [ ] **ملاحظات مفيدة** وترابطًا مع أفكار سابقة؟

### ممنوع

- «نطبّق القانون.» بلا تعليل.
- تعريف مقتضب بلا مثال.
- قاعدة تُعرض بلا سبب.
- خطوة حلّ بلا `why` (النوع نفسه يمنعها).

### مسموح ومطلوب

- إعادة الشرح بزوايا مختلفة حتى يثبت الفهم.
- أمثلة إضافية **موسومة** بأنها إضافية.
- تفاعل يعيد بناء الفكرة بيد الطالب.

---

## 3) مثال أو مثال إضافي؟ لا يختلطان أبدًا

| | من الكتاب | إضافة تعليمية |
|---|---|---|
| الوسم | `provenance: "book"` | `provenance: "extra"` |
| الإلزامي | `bookRef` (صفحة/مثال) | `reason` (سبب الإضافة) |
| العرض | «📘 من الكتاب — ص …» | «💡 توضيح إضافي — …» |
| القاعدة | **لا يُحذف ولا يُختصر** | **لا يحلّ محلّ عنصر كتابي** |

المثال الإضافي يجب أن: يعلّم المفهوم نفسه، يكون صحيحًا رياضيًا، لا يخالف المنهاج،
لا يغيّر ترتيب الكتاب، ولا يدفع أي مثال كتابي خارج الدرس.

---

## 4) شكل الحلّ التربوي

لا قالب واحد للجميع. اختر من أنواع `WorkedSolution` بحسب طبيعة المسألة:

- **`solve`** — مسألة: المعطى → المطلوب → الخطوات (بتعليل) → الجواب → التحقق.
- **`prove`** — برهان: المعطى → المطلوب إثباته → الخطوات.
- **`construct`** — إنشاء/رسم: الخطوات → الناتج.
- **`compare`** — مقارنة/تصنيف: العناصر → الخطوات → الخلاصة.

تدفّق الحلّ الموصى به (يُعدَّل حسب المادة):
المعطى ← المطلوب ← القاعدة المناسبة ← **لماذا تنطبق** ← التعويض ← الحساب ← التحقق ← صياغة الجواب.

---

## 5) التفاعل في خدمة الفهم

التفاعل يُبنى حول المحتوى المقدَّم لا بدلًا منه. الأنواع المتاحة:

`tryYourself` · `revealSteps` · `chooseOperation` · `predictReveal` ·
`matchPairs` · `mistakeHunt` · `figureQuery` · `quickCheck` · `practiceSet`

قواعد:

1. **لا كشف قبل تصرّف الطالب** — لا يُركَّب محتوى الحل في DOM قبل الضغط (لا إخفاء بـ CSS).
   الآلية الملزمة: كل حاوية محتوى محجوب تحمل `data-locked="true"`، والتدقيق الآلي
   يفشل إذا ظهرت هذه العلامة في HTML الأولي. أي محاولة لإخفاء الحل بـ CSS
   بدل عدم تركيبه تُكتشف تلقائيًا.
2. **الاختيار ≠ التصحيح** — لا تغذية راجعة قبل «تحقق من الإجابات».
3. **التطبيع قبل الحكم**: الأرقام العربية-الهندية، الفاصلة العشرية العربية،
   الفراغات، ورموز العمليات كلها تُطبَّع؛ وإلا رُفض جواب صحيح.
4. **لا لعبة بلا هدف رياضي** — كل تفاعل يخدم المفهوم.

---

## 6) الأشكال الهندسية

الشكل من الكتاب **محتوى منهجي**، لذا:

- تُبنى من نقاط إحداثية، وكل العلامات **مشتقّة حسابيًا**:
  زاوية قائمة (من متجهَي الضلعين)، قوس زاوية (بنصف قطر محسوب)،
  تطابق أطوال (شرطات عمودية في المنتصف)، توازٍ (أسهم باتجاه القطعة).
- لا مواضع تقريبية للنقاط أو التسميات (التسمية تُدفع بعيدًا عن مركز الشكل).
- المقاسات والتسميات تبقى مرتبطة بعناصرها ولا تتراكب.
- الرسم متجاوب: `viewBox` ثابت وعرض مرن، فتبقى التناسبات صحيحة على أي شاشة.

---

## 6-ب) صنفان من «الحلّ» — لا يُخلطان

| الصنف | مثال | هل يُحزَّم مع المتصفح؟ | القاعدة |
|---|---|---|---|
| **حلّ تعليمي كاشف** | خطوات حل مثال داخل «جرّب بنفسك» أو «اكشف الخطوة» | نعم (ضروري للكشف التدريجي) | لا يُركَّب في DOM قبل تصرّف الطالب، ويحمل `data-locked` |
| **إجابة تقييمية** | إجابة سؤال اختبار/تمرين مصحَّح | **إطلاقًا** | تُخزَّن خادميًا فقط في `src/content/teacher/**` وتُطلب عبر `/api/grade` |

الفرق جوهري: الأول أداته التعليم (الطالب يرى الحل **بعد** محاولته)، والثاني أداته التقييم
(كشفه يُلغي الغرض منه). لذلك الأول يُحزَّم مع الشرط البنيوي أعلاه، والثاني لا يُحزَّم أبدًا.

- أسئلة الطالب (`StudentQuestion`) **لا تحمل** `answer` أو `why` إطلاقًا.
- التصحيح يتم على الخادم (`/api/grade`): يرسل المتصفح اختيارات الطالب،
  ويعود بـ «صحيح/خطأ + شرح» فقط.
- المفتاح الكامل في `src/content/teacher/**` مع `import "server-only"`،
  ويُقرأ عبر `/api/teacher-key` بعد كلمة مرور المعلم (`TEACHER_KEY_PASSWORD`).
- كل سؤال يجب أن يحمل `why` بالعربية: هذا «حلّ المعلم» على مستوى السؤال،
  وهو ما يجعل الاختبار يعلّم لا يختبر فقط.

---

## 8) قائمة القبول قبل اعتبار الدرس جاهزًا

- [ ] `npm run audit:lesson -- <lesson-id>` ينجح بلا أخطاء.
- [ ] `npm run verify` ينجح (lint + types + اتجاه + اختبارات + تدقيق + بناء).
- [ ] كل نصوص الكتاب موجودة (سجل التغطية يقارنها آليًا).
- [ ] كل مثال كتابي وسْمه ومرجعه صحيحان، وكل إضافة موسومة بسببها.
- [ ] كل خطوة حلّ لها تعليل رياضي مكتوب.
- [ ] الكسور مكدّسة، والمعادلات والمتباينات LTR معزولة.
- [ ] الأشكال دقيقة هندسيًا وتسمياتها مقروءة.
- [ ] الأخطاء الشائعة المذكورة **حقيقية** ولها صلة تعليمية.
- [ ] لا تفاعل يكشف حلّه قبل تصرّف الطالب.
- [ ] لا إجابات في أي ملف يُحزَّم مع المتصفح.
- [ ] قراءة أخيرة كطالب: هل تعلّمت المفهوم؟ إن كان الجواب «قرأت الكتاب» فأعد الكتابة.

> تذكير: البوابات الآلية تُثبت **الوجود والمصدر والاتساق**، ولا تُثبت جودة الشرح.
> الجودة تُراجع يدويًا درسًا درسًا.
